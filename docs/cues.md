# Department cues

Live cue loading, editing, synchronization, and screen rendering are
coordinated in `js/main.js`. The cue creation and editing interface is
encapsulated in the `<cue-editor-dialog>` Web Component
(`js/components/cue-editor-dialog.js` and `js/components/cue-editor-dialog.scss`),
with add-cue controls hosted in `<toolbar-sync>` (`js/components/toolbar-sync.js`).
Visual styling is defined in `css/teleprompter.scss` and `cue-editor-dialog.scss`.
Shared live text-node enumeration, word indexing, and trigger-word wrapping are in
`js/cue-text.js`; anchor positioning uses `js/semantic-position.js`. Server
persistence is handled by `scripts/cue_api.php`. Print-only cue rendering remains a
separate implementation in `js/pdf-export.js` and must stay semantically
consistent with the live view.

## Storage format

Cue documents are stored as ignored deployment data in
`show-cues/<script>_<department>.json`:

```json
{
  "script": "show_id",
  "department": "LX",
  "revision": 1,
  "cues": [
    {
      "id": "lx-example",
      "number": "12",
      "description": "Example cue",
      "color": "#2f80ed",
      "anchor": {
        "type": "word",
        "prompt": "p000123",
        "fraction": 0.4,
        "wordIndex": 7,
        "text": "example"
      },
      "endAnchor": {
        "prompt": "p000126",
        "fraction": 0.25
      }
    }
  ]
}
```

The cue number is required and limited to 24 characters; descriptions are
limited to 120 characters. Colours use six-digit hexadecimal notation. IDs are
stable across edits and are generated by the server for new cues.

## Semantic anchors

Every start anchor contains a stable prompt ID and a `fraction` from 0 to 1
through that prompt. Legacy cues without a start fraction are read as fraction
zero and gain an explicit fraction when saved again.

An anchor is either `paragraph` or `word`. Word anchors additionally retain the
zero-based `wordIndex` and the word text for display and diagnostics. LX, SND,
and STG support trigger-word selection; FS uses paragraph positioning.

`endAnchor` is optional. When present, its prompt and fraction define the exact
end of a cue range. The start and end selection lines follow the teleprompter's
35%-down reference position while the editor chooses them.

## Rendering

Cue badges for paragraph anchors appear before their anchor block. Word-cue
badges occupy a full row immediately before the selected trigger word, even
inside a long dialogue block. Cues sharing a word share a badge holder. The
word remains highlighted with a short connector from its badge. The rail mark,
range start, and Next cue navigation use the word's rendered position so they
follow font-size and responsive reflow. Missing word targets retain the
block-start badge fallback. Script prompt IDs and stored cue anchors do not
change. Print output uses the same placement rule when no annotation margin is
enabled.

When an annotation margin is enabled, badges and END labels are positioned
only in the margin. Their holders no longer insert rows or line breaks into
the script. Thin leaders connect the labels to the word (or semantic paragraph
position); colliding labels are stacked across block boundaries without
overlap. Words on the same text line use separate short routing lanes inside
the margin and slightly offset horizontal leaders below the words. Several
cues may share a word. Badge numbers and descriptions wrap inside the margin;
hovering a cue shows its full label. Left and right margins are supported, and
resizing/font changes recompute placement without changing stored anchors.

A cue with an end anchor also
draws a full-height range line, an exact-position dashed end marker, and start
and end marks in the overview rail. Leader lines can cross the script area;
the badges remain within the selected margin.

For paired lyrics without a margin, a cue at the start of the whole section
spans both grid columns. A word cue within a singer's column stays inside that
column in that mode. With a margin enabled, either singer's cue is placed in
the margin and connected to the relevant word. The same rules apply to the
single-column phone layout and print output.

Cue badges use the script's cue font size and upright, unindented typography,
independent of stage-direction styling. A cue inside a stage direction aligns
with the normal cue edge, or with its own singer column in paired lyrics.
Stage-direction text keeps its original typography and indentation.

Stage-direction blocks directly used as cue start or end anchors remain visible
even when ordinary stage directions are hidden.

## Persistence and synchronization

Public GET requests read a cue document. Mutations require the matching
department password or signed role cookie. `cue_api.php` serializes updates with
`flock`, increments the document revision, and updates
`scripts/teleprompter_state/cue_revisions.json`.

SSE broadcasts the revision map. A matching open department client fetches a
newer document while keeping its existing cue decorations visible until the
replacement arrives. Out-of-order responses after script changes are discarded.

Preserve cue IDs and semantic anchors when changing the format. Test old cues
without `anchor.fraction`, paragraph and word starts, optional ends, backwards
editing, remote revision refresh, hidden stage directions, and annotation
margins.

See `export.md` for cue behavior in print/PDF output.
